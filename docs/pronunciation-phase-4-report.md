# 发音相似阶段四：词典外词补齐

2026-09-22 完成本地实现、预计算与回归验证，未发布到正式站。当前已知缺失的 **84 个单词均生成格式有效的预测读音**。这表示读音可用性，不表示 84 个预测均已由人工确认准确。

## 模型与范围

采用 [Kyubyong/g2p](https://github.com/Kyubyong/g2p) 的 [g2p_en 2.1.0 发布包](https://pypi.org/project/g2p-en/2.1.0/)，上游仓库和发布包标注 Apache-2.0；完整许可保存在 `THIRD_PARTY_LICENSES/G2P-EN-LICENSE.txt`。该模型以 NumPy 执行预训练 seq2seq 神经网络推理。保留权重，抽取上游推理代码，去掉 NLTK 下载、分词、POS 和词典查询副作用，并在解码未终止时明确失败；修改说明保存在代码头部。

| --- | --- |
| 模型版本 | `g2p-en-2.1.0-checkpoint20` |
| 流水线版本 | `g2p-private-v1` |
| 权重 SHA-256 | `b8af35e4596d8dd5836dfd3fe9b2ba4f97b9c311efe8879544cbcfcbd566d8c6` |
| 发布 wheel SHA-256 | `2a7aabf1fc7f270fcc3349881407988c9245173c2413debbe5432f4a4f31319f` |
| 评分版本 | `phoneme-unit-edit-v1` |
| 验证环境 | Python 3.9 / NumPy 1.26.4；CI 配置 Python 3.11 |

输入按 NFKC、大小写、弯撇号和连字符空白规范化。只接受英文单词，可含内部撇号、连字符；组合词按组成部分查词典或预测，不承诺连读、弱读或上下文消歧。输出统一为 39 种 ARPAbet 基础音素，元音必须附 0/1/2 重音，辅音必须无重音。空预测、未知符号或超过解码限制均视为失败，不生成替代音素。

## 私有数据与使用方式

路线图禁止将个人词表或个人索引打包到公共静态资源。阶段四因此采用“本地构建 + 页面导入”：模型和缺失词预计算在本机运行，输出只写入被忽略的 `p0/private/`。公共网站不包含个人补充表，也不新增预测服务。

```powershell
python -m pip install -r scripts/requirements-g2p.txt
npm run build:pronunciation
npm run build:g2p
# 自定义缺失清单：npm run build:g2p -- <文件.txt>
```

构建读取当前缺失清单，验证词典与模型原始字节 SHA-256，排除已有词典读音的单词，生成带模型、词典、评分和流水线版本的 JSON；文件名由内容 SHA-256 决定。重复构建结果一致。任一单词预测失败会记录私有失败清单并以非零退出，已成功条目仍可导入；模型初始化或校验失败直接停止，不伪装成功，也不会选用旧文件。普通 `npm run build` 不隐式运行 G2P。

页面同步词表后，在任一查找入口展开“补充预测读音”并导入生成文件。两个入口共享当前内存数据，补充或移除会终止旧任务、清空旧结果并重置分页；刷新、断开连接或成功切换账号清除补充。导入失败保留之前的有效数据，不触发上传。文件上限 2 MiB、条目上限 10,000；主页面及两个 Worker 入口均校验版本和格式。

## 匹配、资源失败和缓存

- 词典读音优先，补充表只填空缺，不修改公共词典缓存；多音词原有变体不被预测覆盖。
- 双入口使用原来的独立发音召回与 OR 合并。双方均为词典时显示“词典读音”，双方均预测显示“预测读音”，混合时显示两种来源；悬浮说明按左右顺序列出音素及预测模型版本。
- 暂无读音返回 `null` 而非零分，手动未知词明确提示尚不支持实时预测。没有满足任意新词实时预测的需求与部署验证，因此本阶段不启用该条件功能。
- 词典下载、解析或版本失败时，以 `cache: reload` 重读一次；仍失败则清除失败 Promise，下一次任务允许重试。已有私人预测与其他匹配路径继续工作，并显示部分发音数据不可用。
- 预测版本失效或格式损坏时，只跳过预测数据，保留词典和其他匹配类型；关闭发音不加载、合并或计算读音。
- 严格音素校验发现旧转换器把 CMUdict 行尾 `#` 注释当作音素。已修复并发布到新的构建路径 `cmudict-74790861-v2.json`（5,487,527 字节），旧资源保留，避免在 immutable 路径上覆盖内容。公共 126,052 个词条全部通过音素与重音格式验证。

## 验证与限制

新增 6 组 JavaScript 测试、4 个 Python 测试和 4 个浏览器场景；完整套件、类型检查和生产构建通过。覆盖模型异常与非法输出、词典优先、混合来源、关闭发音、缓存失效与重试、网络失败回退、Worker 版本校验、双入口导入和移除、未知词提示、刷新和断开后的清除。CI 新增固定 NumPy 安装。

对阶段一公开样例中 22 个词强制跳过词典直接调用神经模型，20 个输出与至少一种词典变体（含重音）完全一致。发现 `though` 预测为 `TH AO1` 而词典为 `DH OW1`，`turnover` 中 `OW` 的预测重音为 0 而词典为 2；实际产品对这些词使用词典，因此不会采用上述预测。这只是可复现的模型冒烟检查，样例可能在模型训练词典中，不能用作独立准确率估计。独立人工评测、阈值校准及正式发布继续归阶段五。

构建后检查 `dist/` 不包含模型权重、私有预测文件或业务快照；浏览器不调用模型或预测服务。阶段四没有部署正式站。
